## Why a separate edition

Policy section 4B excludes software that uses AI models to generate images. `directory/agybird/` is generated by `scripts/build-directory-edition.mjs` from the same sources as the full plugin with every image-only region removed: no image command, no image category in the runner, no reference images, no image documentation. A test fails while the committed edition differs from its sources. The edition also leaves out the Stop hook and its review gate. The full plugin, with images and the gate, stays in the FINOLABS catalog.

## Example prompts (policy 3E asks for at least three)

1. `/agybird:review` in a repository with uncommitted changes: Antigravity reviews the diff read-only and returns findings by severity, file and line.
2. `/agybird:rescue find why the tests in tests/unit fail and propose the smallest fix; do not edit files`: a read-only investigation handed to Antigravity.
3. `/agybird:usage`: Antigravity quota per pool, local reset times, and the model each tier would use.
4. `/agybird:adversarial-review --base main`: a read-only review that challenges the design of the branch against `main`.

## Points a reviewer will look at

- **Works in Claude Code only.** Every command starts the user's local `agy`; claude.ai chat and Cowork cannot. The edition README says so in its second paragraph. The portal derives surfaces from components (skills load everywhere), so state this again in any free-text field the form offers.
- **Testing account (policy 3D).** A reviewer needs their own Google account with an Antigravity plan and `agy` installed and signed in. Agybird has no account of its own to lend. Offer to demonstrate on a call or with a recording if the reviewers ask.
- **Endpoints (policy 3F).** Agybird itself connects to no endpoint: it starts the official `agy` CLI the user installed, which talks to Google under the user's account. Say this plainly; it is the likeliest reason for a refusal.
- **Delegation only on request (policy 2D).** Commands run only when called; the `agybird-rescue` agent and the skill trigger only when the user names Agybird, `agy` or Antigravity; the edition has no hooks.
- **Expected reviewer holds.** The edition leaves out the Stop hook and its review gate: a command hook from an organization that is not Verified is held, and the portal says such hooks will later be refused. The scripts name no URL, so the credential hold on `scripts/companion.mjs` should not return; `scripts/agybird.mjs` still hands the environment to `agy`, which needs it to sign in. The publisher-name hold (`finolabs`) stays for a reviewer. The portal's notes on `allowed-tools` with Bash and on script files apply to what Agybird is: it runs a Node runner. The edition has no `package.json`, lockfile, package launcher, MCP server or binary.
- **Data disclosure.** The edition README lists what runs, what is sent (to Google through `agy`, including the diff) and what is stored locally. `PRIVACY.md` and `docs/threat-model.md` on `main` hold the full detail.
- **Naming.** `agybird` is a project name of its own; the manifest, README and skill all say Agybird is unofficial and not affiliated with Google.

## After submitting

The directory scans each new commit on the ref it follows. Rebuild the edition (`node scripts/build-directory-edition.mjs`) in the same pull request as any change to a shared file, raise the version with each release, and tell Anthropic about a material change to what the plugin sends or where (policy 3H).

# OpenAI Codex plugin directory

Prepared for Fio to submit from the OpenAI plugin submission portal. Nothing has been submitted. Sources read on 2026-11-12: OpenAI's [plugin submission](https://developers.openai.com/plugins/deploy/submission), [desktop-only plugins](https://developers.openai.com/plugins/deploy/desktop-only) and [build plugins](https://developers.openai.com/codex/plugins/build) pages.

## What to submit

| Field | Value |
| --- | --- |
| Path | **Create plugin** → **Skills only** → **Upload ZIP** (desktop-only: Agybird runs the local `agy` CLI) |
| ZIP | `dist/agybird-codex-<version>.zip`, built by `node scripts/build-codex-edition.mjs` from the release tag (needs `zip`) |
| Manifest | `.codex-plugin/plugin.json`, legacy layout, with `requires_local_executor: true` at the top level |
| Default prompts | the three `interface.defaultPrompt` entries in the manifest |
| Release notes | the version's section of `CHANGELOG.md` |

The ZIP holds the Codex skills, the runner and companion, the prompts, schema, references, icons and license. It leaves out `hooks/`, because OpenAI does not accept plugins with lifecycle hooks and Codex loads `hooks/hooks.json` on its own; the review gate goes with it, and `$agybird-setup` in this edition neither offers nor accepts it. Claude-only parts (commands, the Claude agent, the Claude and Antigravity manifests) are left out too. Image generation stays: the OpenAI pages name no restriction on it.

## Before submitting (Fio)

- Complete individual or business verification in the OpenAI organization settings, and submit as the organization owner or with Apps Management Write.
- Desktop-only plugins may need allowlisting: if the portal rejects `requires_local_executor`, send the organization ID to an OpenAI representative and wait for confirmation.
- Test a clean Codex desktop install of the unpacked ZIP and the main skills first.
- The policy attestations in the portal are Fio's to make.
