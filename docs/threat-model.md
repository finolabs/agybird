# Agybird Threat Model

## Scope and assets

Agybird protects the user's local workspace, prompt content, Antigravity authentication boundary, provider configuration, subscription credits, and the integrity of generated artifacts. It trusts the user-selected workspace, the locally installed Node.js runtime, the resolved official `agy` binary, and Google Antigravity only within their documented roles.

It does not attempt to secure a compromised operating system or a malicious official provider service.

## Data flow

The orchestrating agent sends a prompt over stdin to the Node.js runner. The runner constructs an argument array and spawns `agy` with `shell: false`. Antigravity reads the selected workspace, requests permissions under its own configuration, and emits NDJSON on stdout. Agybird normalizes those events and verifies image artifacts inside the workspace.

The runner also resolves an Antigravity project for the workspace and passes `--project`, because a conversation is bound to its project when it is created. With `--grant` it writes user-approved allow-rules into that project file under `~/.gemini/config/projects/`.

To keep one objective inside one conversation, the runner records the workspace's conversation id under `~/.agybird/sessions/`, one file per workspace, and resumes it on the next run. While a grant is applied it also holds a lock under `~/.agybird/grant-locks/`. The commands add a job store (the plugin data folder or `~/.agybird/jobs/`) with each job's prompt, result and log, the review gate switch and a quota cache. These are the only places Agybird writes outside the workspace; it never writes inside the repository.

With the opt-in desktop transport, the companion starts `scripts/desktop.mjs` instead. That runner drives the Antigravity desktop app through the macOS Accessibility API, one `osascript -l JavaScript` call per step: it opens a new conversation in the workspace's project, pastes the task through the app's own Edit > Paste, presses Send, reads the window to tell when the turn ends, and copies the reply with the app's Copy button. It writes `~/.agybird/desktop.lock` while it acts on the app, a record per run in `~/.agybird/desktop-runs/`, and, for a folder no project points at, a new project file in `~/.gemini/config/projects/`.

The commands run through `scripts/companion.mjs`, which never runs `agy` for work itself: it collects the git diff for reviews (with the repository's git programs switched off), picks a model from `agy -p /usage` and `agy models`, and starts the runner as a child with the prompt on stdin, in the foreground or as a detached worker. The opt-in review gate is a Stop hook that does the same for the turn's uncommitted changes.

## Threats and controls

| Threat | Consequence | Control | Residual risk |
| --- | --- | --- | --- |
| Executable substitution on PATH | A malicious binary impersonates `agy` | Resolve and report the concrete executable path and version; document that users should install only from the official [install guide](https://antigravity.google/docs/cli/install) | A compromised account or PATH can still replace an executable |
| Malicious prompt | The delegated worker is instructed to widen scope or disclose data | Require explicit category and workspace, default to read mode, preserve Antigravity permissions, neutralize closing task delimiters, enforce untrusted data boundaries, and independently inspect outcomes | Provider reasoning can still make mistakes within allowed access |
| Malicious repository instructions | Repository content attempts prompt injection or unrelated file access | Treat repository text as untrusted when it conflicts with the user task; bound verification to requested files | Read access can expose sensitive files already inside the workspace |
| Oversized output | Memory exhaustion or terminal flooding | Limit provider output to 16 MiB and prompt input to 1 MiB; terminate the child on overflow | Limits are per invocation, not an operating-system resource sandbox |
| Artifact path spoofing | A provider claims an unrelated local file as generated output | Resolve canonical paths; require containment in the working directory or the exact `brain/<conversation_id>` provider artifact directory; require a supported raster extension, nonzero size, and a completed image tool event | File content can still be visually wrong or maliciously crafted |
| Permission soft-denial with exit zero | A blocked write is falsely reported as success | Inspect stderr and tool statuses for soft-denial evidence and normalize the result to `needs_permission` or `blocked` | New provider wording may require parser updates |
| Unapproved permission grant | A calling agent passes `--grant` for a rule the user never approved, widening what the next run may do | Refuse `--grant` when the workspace has no recorded session and when it accompanies `--new-session`, restrict rules to the allow-rule kinds `agy` recognizes, require the target to be an escaped literal rather than a regular expression so no spelling of a wildcard is accepted, refuse targets holding no letter or digit, journal the undo before applying a `once` grant so a killed run is repaired by the next one rather than leaving the rule on disk, hold a per-workspace lock for the length of the grant, taken by publishing the next lock generation so that a stale lock is superseded rather than deleted and no lock can be taken twice, so a run on a different conversation cannot start and inherit it, and have every run register before it checks that lock while the grant checks the registered runs after taking it, so a run already going on another conversation makes the grant wait instead of inheriting it, and default `--grant-scope` to `once` so an unapproved rule cannot outlive one run | Each run is a separate process holding no state, so the runner cannot prove a rule came from a request it previously reported; the caller remains responsible for asking the user |
| Overbroad grant request | Antigravity asks for a rule far wider than the denied call, such as `command(git)` for one `git log` | Validate rule targets against literal grant constraints, withhold suggestions and mark ungrantable when targets contain wildcards or lack identifying tokens, report the requested rule verbatim in `permission_requests[]` from the `ask_permission` payload so the user approves the real scope, and document preferring the narrowest target | A user who approves a wide rule with `remember` keeps that access for the repository |
| Permission-request prompt injection | Untrusted stream text in a denial reason is rendered to the user or an agent as if it were an instruction to approve | Expose tool, target, and rule as separate structured fields, flatten and truncate the rendered ones to 300 characters, flag with `target_truncated` that the rule covers more than was shown, and require callers to render only those fields | A caller that ignores the contract and pastes raw text can still be misled |
| Unintended session reuse | An unrelated objective silently inherits an earlier conversation, so one task's context and instructions carry into another | Scope the recorded conversation to a single workspace, resume only ids Agybird itself recorded, require `--new-session` to start over, and report which happened in `evidence.session_resumed` | A caller that never starts a new session keeps appending unrelated objectives to one conversation |
| Session store corruption or loss | An interrupted or concurrent write leaves the store unreadable, dropping recorded sessions | Keep one file per workspace rather than a shared map, so a run only ever writes its own record and neither a concurrent write nor a damaged file can reach another workspace; key on the canonical path and write through a temporary file and rename | Two runs in the *same* workspace can still overwrite each other's record, but both hold a valid conversation for it |
| Session store disclosure | `~/.agybird/sessions/` collects the paths of every workspace Agybird has run in, alongside their conversation ids | Record only the workspace path and conversation id, never prompts or results, and keep the file in the user's own home directory | Any process running as the user can read it, though the same process can already read Antigravity's credentials and conversation history |
| Repository-configured git programs | Collecting a diff for review runs a fsmonitor, textconv, external diff or filter command that the change itself modified | Run every `git` call with fsmonitor, the untracked cache and external diff off and `--no-textconv`; blank every configured filter driver, and refuse the review when the driver list cannot be read completely; on git 2.41+ read attributes from the empty tree; bound each call in time | A program configured outside git's own settings (a shell alias, a wrapper on PATH) is out of reach |
| Repository content escaping its data block | A file name or diff text closes the untrusted-data delimiter and reads as instructions | Fill prompt templates in one pass, keep file names, the agent message and the diff in their own delimited blocks, and escape closing tags inside them | The model may still follow injected text it reads as data |
| Approval of a request nobody reported | Provider prose fabricates a permission request, or an approval for one conversation lands in another | Approve by `<job>:<n>` only; take the rule from that job's stored `permission_requests`, require it to be grantable, and resume that job's own conversation, mode, category and model; refuse approvals from two conversations | The user still decides what to approve |
| Background job outliving its session | A worker or agy keeps running, or a stale pid is signalled | Only the worker stops its runner, through the child handle it owns; cancel marks the record under a per-job lock and waits for the worker; liveness follows a heartbeat; a job past its deadline settles as failed and its pid is reported, never signalled | A runner whose worker died is left for the user to end |
| Review gate cost and loops | Every turn spends quota, or Claude and the gate block each other indefinitely | Off by default and per repository; runs only with uncommitted changes, on a light-tier model, inside a 12-minute deadline; never blocks when `stop_hook_active` is set; fails open with a notice | Each gated turn with changes still spends quota |
| Job store disclosure | Prompts and diffs of past jobs stay on disk | Store under the plugin data folder or `~/.agybird/jobs/` with owner-only permissions, never in the repository | Any process running as the user can read it |
| Unattended commands under the app's preset | Under `Auto` or `Turbo` the app runs commands and edits files the user never saw | The preset is the user's setting and the runner never changes it; the envelope records it in `evidence.preset` and warns under `Auto` and `Turbo`; read mode compares file hashes and `HEAD` before and after, and when the app asks for a permission, and turns any change into `error`, declining that prompt, naming the files | The check detects a change after the fact and cannot prevent it or undo it, and it cannot see effects outside the repository |
| Accessibility control of the wrong app | Input meant for Antigravity reaches the calling agent or another app, as a stray Escape once cancelled the caller's own turn | Send no keystroke at all: act only through AX attributes, AX actions on Antigravity's own elements, and Antigravity's own menu items; bring the app to the front before pasting and verify the pasted text reads back before Send | The Accessibility grant belongs to the host app and covers every app, so a compromised host process could misuse it regardless of Agybird |
| Reading or stopping the wrong conversation | The user opens another conversation mid-run, and the runner returns its reply or presses its Stop | End every prompt with a per-run random marker line (`[agybird-run <hex>]`, after any reply instructions, which the prompt asks the agent to ignore); paste, clear and Send only while the untitled new conversation shows; bind the run's conversation to the title read in the same call that pressed Send, and only in a read that shows, under that title (inside the titled web area, outside the agent's replies and the sidebar, which 2.36 draws inside that web area), the run's own message with that marker, so neither a conversation that existed before Send nor one the user creates, sends and gets titled during the naming wait is adopted; never bind to a title seen later, except that a bound conversation the app renames (2.36 renames a new conversation a few seconds after Send) is followed to a new title of the same project only in a read that shows the run's own message with its marker under it; require the title and the marker in the same read as every poll, Copy, Stop and answer, and as the on-screen evidence that frees a kept lock (the sidebar evidence below carries no marker); any other title, the right title without the marker (a namesake), or a message the tree does not show ends the run with an error and nothing pressed; an approval carries the asking run's marker from its stored envelope and is refused without it; take every control read or pressed (the dialog's option 1, Skip and Submit, Copy, Stop execution, the reply and the running state) only from inside the verified conversation's subtree, the single titled web area carrying the marker, and fail closed, nothing pressed, when the tree holds a second titled conversation (another window or pane) or such a control outside that subtree; take the composer pasted into or cleared and the Send pressed only from inside the single titled web area showing the untitled new conversation (no marker exists before Send), and only when it is the one composer or Send in the whole tree, failing closed, nothing pasted, cleared or sent, on a second one anywhere (an untitled pane's included) or one outside that web area; never take a tree read cut off at its 20,000-node cap for the whole app, since a rival conversation or control, the Stop that shows a run, or the rest of a reply may lie past the cut: before Send it fails closed with nothing pasted, cleared or sent, an answer on it presses nothing, and after Send it is never a finished turn, so the run waits to its deadline and presses Stop only from a whole read, otherwise keeping the lock for the app | On 2.36 a sent message is collapsed but its whole text, marker included, is one accessibility text (verified live on 2.36.0); a message shown shortened or left out of the tree fails closed; with renames followed, the marker, not the title, carries the conversation's identity after Send; that the app renders its composer, Send, permission dialog, Stop button and Copy inside the conversation's web area, and one titled conversation at a time, is assumed and not verified live: otherwise every run fails closed until it is checked; the marker is not secret, so a conversation into which someone pastes the run's prompt, marker line included, would pass the check; while the app's tree stays past the node cap, every run fails closed, ending `error` or keeping the lock for the app |
| On-screen text as instructions | Text in the app window, a reply or a permission prompt steers the caller | Treat the reply and the prompt's question as untrusted data, flatten the question, show it whole up to 4,000 characters (the `target` is cut to 300), refuse to approve a longer one, and render only structured fields | A caller that pastes raw text can still be misled |
| Clipboard exposure | The task (which can hold a review's diff) or the reply is read by another app from the clipboard, kept by a clipboard manager, carried to other devices by Universal Clipboard, the user's clipboard is lost, or it is stored as the reply | Write the task current-host-only and marked `org.nspasteboard.TransientType` and `org.nspasteboard.ConcealedType`; hold it only until the paste lands, then restore what the clipboard held, saved whole (every type of every item, up to 16 MB; past that its plain text with the markers it carried); read the reply back in the same call that presses Copy (only when the pasteboard changed) and restore right after; warn when a clipboard too large to save whole held non-text content; give a cancelled or interrupted (Ctrl+C, host timeout) desktop run 20 s to clean up before it is killed, bound each of cleanup's app calls (16 s together at most for a run holding the app; a run waiting with the app free fits taking it back and Stop within 18 s of the signal), and cut short the step in flight so a long paste cannot outlast that grace | Any app polling the clipboard can read the task or the reply in those windows; the reply is written by the app's Copy button without the markers, so a clipboard manager or Universal Clipboard may pick it up; markers only help managers that honour them; an image, a file or rich text on a clipboard past 16 MB is not restored; a run killed before cleanup leaves the task on the clipboard |
| Approval spoofing in the app | An approval answers a different or wider prompt than the user saw, one in another conversation, or a later prompt with the same words | Approve one stored request at a time, once, on the transport the job ran on; in the same accessibility read that presses it, require the conversation that asked (its title and the asking run's own message with its marker), the whole question, read from every text node of the dialog's own group and compared uncut, and option 1's exact label, pressing option 1 and Submit only inside that same group, itself inside the verified conversation's web area with no second titled conversation in the tree, "Yes, allow this time", never the options that allow for the conversation or always; a decline answers Skip under the same checks; an answer whose step fails after it may have pressed (timeout, crash, failed press, cancel) is treated as pressed: spent, reported as uncertain, and followed by Stop in that conversation or a lock kept for the app; the runner creates a per-request answer mark in the job store, exclusively, before the answer's step starts, refuses to press when it cannot or when one exists, and removes it only on a refusal the app reports before any press; an interrupted foreground approval also waits for the runner and records the result before exiting, so no interruption, a kill during the press included, can leave a pressed approval unspent | The question names the action, not the exact command line, so the user approves what the app shows; the app draws an agent's question and a permission prompt alike, told apart only by option 1 reading `1 Yes, allow this time`, so an agent steered to ask a question with that very option 1 is reported as a permission prompt (the user still sees its whole text before approving, and the answer is pressed once, never a lasting grant) |
| App update changes the window | Renamed controls make the runner press the wrong element | Require the tested app version range unless the user confirms; require every control label before acting and block with `labels_missing` otherwise; select a project by its name only when no other project shares it | A change that keeps the labels but moves their meaning would not be caught |
| Concurrent desktop runs | Two runs paste into one app and one clipboard, read or press in each other's conversation, or a new run starts while the app still runs an abandoned task | Up to five runs at once, counted under the lock from per-run records (`desktop-runs/<marker>.json`, written whole through a rename, removed by their run; a record whose process is gone is removed, unless it says the app may still run its task, from Send on: that one counts until the sidebar shows its conversation alone and Idle, or the user removes it); a new project is created under the lock, so two runs never create two projects of one name; the lock is held only while a run acts on the app: from the switch to the app until its conversation's title has settled after Send (a rename, or 15 s), and again to read its result, answer or Stop. While its agent works a run reads only its own sidebar row (title and project, status heading In Progress, Blocked or Idle), read only inside the one `Sidebar` group so a conversation's text shaped like a row or a heading is never taken for one, with no lock; to act it takes the lock back, opens its row from the sidebar and checks its title and marker in the same read before reading or pressing anything, pressing only that conversation's own `Load older messages` (never one in the sidebar) when the title matches and the marker lies before the steps shown; a run that cannot take the app back within a cancel's grace says Stop could not be pressed. A turn ends only once the sidebar shows no row of its title In Progress; a failed read, or no row, decides nothing, and three reads in a row with no row end the run. A run that takes the lock back holds the app from then on, so a failure while it opens its row never waits on its own lock. A machine-wide lock file, `desktop.lock`, linked into place whole with the run's pid and an expiry past its deadline; one being written counts as held for a minute; from just before Send or an answer the lock is marked as kept for the app, with the conversation's title once bound and the run's marker, so a run killed at any point, a stalled Stop included, leaves it; a kept lock never expires on time alone and is freed only when a later run, its holder gone, reads the app showing that conversation (its title and its run's marker in the same read) with no run and no prompt, in a whole read, never one cut off at the node cap, or, only while a whole read shows another conversation, finds the sidebar listing that conversation alone and under Idle in the project the lock recorded, or when the user removes it, as the `locked` message says; a stale lock is removed only by the run holding a takeover guard (`desktop.lock.takeover`, created exclusively), after it reads the lock again, so two runs can never both hold it; the temporary file is created exclusively and never written through a planted link | A run of another tool driving the app is not seen; a kept lock with no bound conversation, or whose holder's pid was reused, waits for the user to remove it; a namesake conversation of the same title In Progress in the same project delays the end of a run's turn until it ends or the run times out; sidebar rows carry no marker, so a kept lock or record whose conversation is the only one of its title in its project under Idle is freed even if that row is a namesake while the kept one was archived or renamed before its run recorded the new title |
| Supply-chain compromise | Dependencies or CI actions execute attacker code | Keep zero runtime dependencies, commit the lockfile, pin GitHub Actions by full SHA, and use least-privilege workflow permissions | Node.js, `agy`, Git, and the Skills CLI remain external dependencies |
| Local data disclosure | Prompts, credentials, or unrelated files reach logs or outputs | Accept prompts on stdin, avoid credential stores, redact raw provider diagnostics (the envelope carries a bounded, flattened excerpt of agy's error message, and raw stderr stays out), and avoid persisting live prompt bodies | The official provider receives task context needed to perform the work |

## Policy and authorization boundary

Agybird never reads Antigravity's credential cache, changes `useG1Credits`, calls private endpoints, or passes `--dangerously-skip-permissions`. It does not bypass subscription eligibility, quota, sandbox, permissions, or content policy. Use remains subject to the [Antigravity terms](https://antigravity.google/terms).

The desktop transport drives only the Antigravity app, reads and presses only in the conversation it started (checked by its title and, in the same read, the run's own message with its marker), and never changes the app's settings, model or permissions preset.

Agybird never invents an allow-rule. A rule reaches `--grant` only after the user approves the request the runner reported, and the runner widens no permission on its own.

Review this model when the official [headless event format](https://antigravity.google/docs/cli/headless), artifact behavior, or security boundary changes.
