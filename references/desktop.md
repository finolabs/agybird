# Desktop transport

Read this when the user chose the desktop transport (`/agybird:setup` or `$agybird-setup` reports `Transport: desktop`) or passes `--via desktop`. The CLI stays the default; nothing here applies to it.

## What it is

The runner `scripts/desktop.mjs` takes the same arguments, the same prompt on standard input and returns the same envelope as `scripts/agybird.mjs`, but the task runs in a new conversation of the Antigravity desktop app on macOS. It drives the app through the macOS Accessibility API: it sends no keystrokes, presses only the app's own controls and menu items, and touches no other app except to bring the user's front app back afterwards. The envelope carries `evidence.transport: "desktop"`, `evidence.app_version`, `evidence.preset` and `evidence.changed_files`.

```bash
command node "/absolute/path/to/agybird/scripts/desktop.mjs" \
  --category code \
  --cwd "/absolute/workspace" \
  --mode read <<'AGYBIRD_PROMPT_7F3A'
Explain how the parser handles empty input.
AGYBIRD_PROMPT_7F3A
```

Every run starts a new conversation; there is no resume. The runner pastes and presses Send only while the app shows the new, untitled conversation, and the same step that presses Send waits up to 30 seconds for the app to title it. That title identifies the run's conversation only when its name was nowhere in the window (the sidebar's conversation list included) just before Send and appears there afterwards, so a conversation that already existed is never adopted; the runner then reads, copies and presses only while the app shows it. A title that appears only later is never adopted. If you open another conversation in the app during a run, even before it is titled, the run ends `error` without touching it, and so does a run whose new conversation is named like one already listed. The runner refuses `--category image`, `--swarm`, `--grant`, `--model`, `--effort`, `--agent`, `--sandbox` and `--conversation`, naming the flag: the app uses the model and settings chosen in it. Image work, usage and the review gate always use the CLI. `--json-schema` asks for one fenced JSON block at the end of the reply; the runner checks its top-level `required` keys and returns it as `structured_output`.

## Before a run

Grant Accessibility to the app that runs Agybird (the terminal, Claude, Codex or ZCode) in System Settings > Privacy & Security > Accessibility, then start a new session: a grant reaches only processes started after it. The workspace folder must already be a project in the app; the runner finds it in the project list the app shares with the CLI and opens a new conversation in it.

While the prompt is pasted (about a second), the app comes to the front and the clipboard holds the prompt, written on this Mac only and marked transient and concealed for clipboard managers; the clipboard is put back as soon as the paste reads back, the front app after Send, and the clipboard again right after the reply is copied (the app's Copy button writes the reply unmarked). Only the clipboard's text is put back: an image, a file or rich text on it is lost, and the run warns. Ask the user not to type into the app during that moment. If the pasted text reads back differently, the runner clears the input and sends nothing.

`blocked` names its reason in `evidence.blocked_reason`: `not_macos`, `app_missing` (open the app), `not_trusted` (grant Accessibility, new session), `unsupported_version` (outside the tested 2.35.x; the user may confirm with `AGYBIRD_DESKTOP_ALLOW_VERSION=1`), `labels_missing` (another app version or language), `no_project` (open the folder as a project in the app), `ambiguous_project` (two projects share the name; rename one), `locked` (another desktop run is in progress, or an earlier one may still be going in the app).

## Permissions

The app's permissions preset is the user's own setting: the runner accepts `Request Review`, `Default`, `Auto` and `Turbo` and never changes it. Under `Auto` and `Turbo` the app may run commands and edit files without asking, and the envelope warns so. Read mode then only detects changes after the fact: any change to the working tree, or a moved `HEAD`, makes the run `error`, and `changed_files` names the files. Files git ignores are not compared. In write mode `diff_stat` adds the added and removed lines of each changed file, against `HEAD`.

When the app asks for a permission, the run ends `needs_permission` with the app still waiting. Each request carries the app's whole `question` (read from every text of the dialog), the rule `scope` its wider options name, and the `options` shown. Put the question in front of the user. A question longer than 4,000 characters is shortened, `question_truncated` is set and `approvable` is false: it can only be answered in the app. Approving answers "Yes, allow this time" once: `companion.mjs task --approve <job-id>:<n>` with no other flag. In the same read that presses it, the runner checks that the app shows the conversation that asked, the same whole question and that exact option, all inside the one dialog it presses, and refuses otherwise, also when two dialogs on screen ask the same question. If the run had already changed the working tree in read mode, the runner declines the prompt and the run ends `error` instead. Each request is answered once; it counts as answered from the moment the runner starts to press the answer, so only an approval whose run stopped before that (another desktop run held the app, for example), or whose answer the app refused before any press (another conversation or question on screen, a changed option 1), can be given again. When the answer's own step fails in a way that may come after the press (a timeout, a crash, a failed press, a cancel during it), the runner treats it as pressed, like an uncertain Send: it presses Stop in that conversation or keeps the lock for the app, sets `evidence.answer_uncertain`, and the request counts as answered. The runner records the answer in the job store (`<job>.answered-<n>`) before it starts to press it, and removes the record only when the app refused the answer before any press, so an approval interrupted at any point from then on (Ctrl+C, the host's timeout, or a kill, during the press included) is spent; a record already there stops the run before anything is pressed; an interrupted foreground approval also waits for the runner to finish and records its result before it exits. When the user declines, `companion.mjs task --decline <job-id>:<n>` answers Skip in the app with the same checks, so the agent hears the refusal instead of waiting. Agybird never presses the options that allow a command for the whole conversation or always; when the user wants that, they answer in the app themselves. A run that reaches its deadline is stopped in the app, and so is one that is cancelled, interrupted (Ctrl+C or the host's own timeout gives it the same 20 seconds as a cancel, more than its cleanup's bounded app calls can take) or that fails after Send; a cancel cuts short the step in flight, a long paste included, and clears a prompt pasted but not sent. From just before it presses Send or an answer, the run marks `desktop.lock` as kept for the app, with the conversation's title once known, so the lock survives the run however it ends. When Stop cannot be pressed in the run's own conversation, the run says the app may still be going and leaves that lock in place. It never expires on time alone: a later run is admitted only once it finds the app showing that conversation with no run, and otherwise ends `blocked` with reason `locked`, naming the conversation and the lock's path, which the user may remove once the app runs nothing for it.
