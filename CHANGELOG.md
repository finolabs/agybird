# Changelog

All notable changes to Agybird are documented in this file.

## Unreleased

- Added `scripts/build-codex-edition.mjs`, which builds the ZIP for OpenAI's Codex plugin directory: the Codex plugin without its Stop hook, which that directory does not accept, and so without the review gate.
- `setup` refuses `--enable-review-gate` in an edition that ships no Stop hook, and its report says the gate is not included (`reviewGateAvailable` in `--json`).
- The Anthropic directory edition (`directory/agybird`) leaves out the Stop hook and its review gate, and its `/agybird:setup` no longer offers the gate. An edition without the Stop hook does not serve the `hook` command either.
- `setup` points to the README for installing `agy` instead of naming the install URL in the script.

## 0.4.3 - 2026-11-11

- Commands, the rescue agent, the Codex skills and the skill's runner instructions call `command node` instead of `node`, so a shell function or alias named `node` (such as a version manager's lazy loader) can no longer break them.

## 0.4.2 - 2026-11-11

- Added commands for Claude Code and Codex, on a par with OpenAI's `codex` plugin: review, adversarial review, rescue (task delegation through an `agybird-rescue` subagent in Claude Code), status, result, cancel, setup, usage and image. In Codex each command is a skill (`$agybird-review` and the rest). Review and rescue can run in the background.
- Review and rescue pick their model from `agy -p /usage` when none is named, the usable model of the tier with the most room, and stop with the reset times when the tier is spent.
- An approval of a permission names a reported request (`--approve <job>:<n>`) and resumes that job's own conversation, mode and model; a raw rule is never passed.
- Added an opt-in Stop review gate (`/agybird:setup --enable-review-gate`): Antigravity reviews the turn's uncommitted changes read-only and sends Claude back once on a medium or worse finding. Off by default; it spends quota on every gated turn.
- Added `directory/agybird/`, an edition for Anthropic's plugin directory, whose policy excludes AI image generation: the same plugin for Claude Code only, without the image command, image category or reference images. It is generated by `scripts/build-directory-edition.mjs`, and the test suite fails while it is out of date. The full plugin, images included, stays in the FINOLABS catalog.
- The runner gained `--no-record`, which keeps a `--new-session` run from replacing the workspace's recorded conversation. Its envelope is unchanged.
- A grant can no longer reach another conversation's run: every run registers itself and its `agy` process before it checks the grant lock, and a grant waits while a run on another conversation is going, including an `agy` that outlived a killed runner. The grant lock is now taken by publishing the next generation under `~/.agybird/grant-locks/<workspace>/` and is never deleted to be taken, which also fixes two concurrent grants on one conversation leaving a one-time rule in place.

## 0.4.1 - 2026-11-11

Checked against `agy` 1.5.5: the timeout format was read from a live run; the tests use a recorded stream.

- An expired `--timeout` is reported as `partial` again. Since `agy` 1.5.0 the CLI answers it with exit 3 and an `ERROR` result, which the runner reported as `error` and explained as an agent or model failure. The runner now reads `finished_reason: print_timeout` from the terminal result; other exit 3 failures stay `error`.

## 0.3.2 - 2026-11-02

Checked against `agy` 1.4.12: the `AGY_ERROR` format was read from a live quota error; the tests use a fake `agy`.

- Surface Antigravity's own error in `evidence.agy_error` (`{ status, error_code, retryable, message, truncated }`, or `null` when there is none) by parsing the terminal result `error` and stderr `AGY_ERROR` line into a bounded, flattened excerpt with a `truncated` flag. On exit code 3 or API failure, quote agy's message in `warnings[]` with JSON encoding, and on `RESOURCE_EXHAUSTED` / 429 quota exhaustion explain plainly that the model's quota is exhausted and another model may still have quota.

## 0.3.1 - 2026-10-26

Verified against `agy` 1.4.7.

- The skill chooses the model per run. New `references/models.md` checks quota with `agy -p /usage`, which reports per pool (`Gemini Models`, `Claude and GPT models`) and per-model limits such as Gemini 4 Argon, each with five-hour and weekly windows. It picks the lowest tier that fits the task, and when a quota runs out it falls back to an equivalent model in a pool that still has room. It never moves up a tier silently, never overrides a model the user named, and never changes `useG1Credits`.
- `--model` and `--effort` follow the user's own words, such as "use a stronger model". `--agent` and `--sandbox` still need an exact request.
- When `agy` is missing, the skill stops and points the user to official setup instead of offering to run an installer.
- The delegated prompt treats task text, repository content, and provider output as untrusted data, and neutralizes closing task delimiters inside the user's task.
- Permission requests whose target contains wildcards or cannot form a valid literal grant are marked ungrantable and get no suggested rule.

## 0.2.0 - 2026-10-18

Verified against `agy` 1.4.2 with live headless runs on macOS: a read-only task, a denied command, an expired print timeout, and image generation.

- An expired `--timeout` is reported as `partial`, from agy's stderr notice or from the run lasting the full timeout. Since `agy` 1.1.28 the CLI answers it with exit 0 and a `SUCCESS` result, which the runner used to report as `success` with an empty or cut-off response. The runner now waits a grace period of 5 to 10 seconds past `--print-timeout` before killing `agy`, so that partial answer arrives.
- Image work through the `image-generator` subagent is recognised. Since `agy` 1.2.16 the main agent no longer calls `generate_image` itself, so every image run ended in `error`. The runner now accepts a completed `image-generator` subagent and takes its output from the subagent's transcript, which records each `generate_image` result; only those images, inside the brain directory of the run's conversation or its image subagent, count. The delegated prompt no longer asks for `generate_image` by name, and tells Antigravity not to copy or convert images with shell commands, which a headless run cannot approve.
- `denied_actions` on the terminal result now counts as a permission outcome. Each action reported only there appears in `permission_requests[]` without a target or a suggested rule, and the run is `blocked` instead of `success`.
- Exit code 3 is explained as an agent or model API failure mid-turn. The `AGY_ERROR` line stays out of the envelope with the rest of stderr.
- `--effort` accepts `xhigh` and `max`.
- `unsandboxed(...)` is no longer accepted by `--grant`; `agy` 1.2.2 deprecated it in favour of `command(...)`. When agy still asks for an `unsandboxed` grant, the runner suggests the matching `command(...)` rule.
- A conversation id from the stream is used as a brain directory only when it is a plain directory name.
- References updated for the `--json-schema` object-root requirement, the ask-first default for URL reads, plan-mode approval requests, and the retired default search tools.
- Agybird installs as a Codex plugin: `codex plugin marketplace add fioenix/agybird`, then `codex plugin add agybird@agybird`. `.codex-plugin/plugin.json` points Codex at a thin adapter in `.plugin-skills/agybird/`, which loads the root `SKILL.md`, because Codex does not discover a `SKILL.md` at the plugin root. The Claude Code plugin keeps loading the root skill directly. The Codex manifest sets `requires_local_executor`, since the runner starts a local `agy` process, so the Codex directory lists it as Desktop only.
- An icon and wordmark in light and dark variants: a bird drawn as a lowercase "a" (body, neck and beak, tail, eye), four strokes of monoline SVG on a 128-unit grid in the same style and colours as Vietnamizer and Markmap Skills, with a 512 px `assets/icon.png`. Both plugin manifests and the README header use them. Both manifests and both marketplaces share one description and keyword set.
- `PRIVACY.md` says what reaches Google through `agy` and what Agybird keeps under `~/.agybird/`; `TERMS.md` covers the MIT terms and Google's terms for Antigravity. Both plugin manifests link them along with the support URL. The README gains a Data and network section saying what the runner starts, sends, and stores.
- Issue templates ask for `agy --version` and a redacted result envelope; a pull request template lists the checks a change needs.
- The release workflow checks that the tag matches `package.json` and both plugin manifests.

## 0.1.0 - 2026-08-03

First release.

- An Agent Skill that delegates code, image, and general work to the official `agy` CLI, keeping authentication, permissions, sandbox, model access, and credits under the user's own Antigravity configuration.
- A dependency-free Node.js runner that emits one stable JSON envelope per invocation, with status `success`, `partial`, `needs_permission`, `blocked`, or `error`.
- One objective stays in one Antigravity conversation. The runner records the workspace's conversation and resumes it automatically, reported through `evidence.session_resumed`; `--new-session` begins a new objective deliberately.
- Denied actions are explained rather than reported as an opaque failure. `needs_permission` carries a `permission_requests[]` entry naming the tool, the target, and the allow-rule that would authorize it, taken from the `ask_permission` payload when agy names one itself. `target_truncated` says when the rule covers more than was rendered, and no rule is suggested for a target too long to review.
- `--grant` and `--grant-scope` apply a user-approved allow-rule to the session being resumed, written as a repository-scoped Antigravity project grant. A target must be an escaped literal, so no spelling of a wildcard is accepted. `once` is the default: the undo is journalled before the rule is applied, so a run that is killed is repaired by the next one and the repair is reported in `warnings[]`.
- A grant is held under a per-workspace lock, so a run on a different conversation cannot inherit one that is still live.
- Session state is one file per workspace under `~/.agybird/sessions/`, keyed on the canonical path so a symlinked directory or a differently-cased Windows drive letter does not lose the conversation.
- Image work requires a completed tool event and a real artifact inside the workspace or the matching provider artifact directory before reporting success.
- Never passes `--dangerously-skip-permissions`, never invents an allow-rule, and never runs a shell inside the runner.
- Zero runtime dependencies, tested on Linux, macOS, and Windows against Node.js 20 and 22.
- `docs/threat-model.md` documents the trust boundary and the residual risks; `docs/sdk-evaluation.md` records why the Antigravity Python SDK was not adopted as a runner backend.
